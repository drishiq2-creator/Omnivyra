# W6 baseline-gap replay manifest.
#
# WHAT THIS IS. supabase/_schema/baseline.sql is a schema-only dump of production
# at ledger position baseline.json `ledgerMax`, and scripts/ci/real-schema-ci.sh
# replays only migrations ABOVE that position. A migration at or below ledgerMax
# whose objects are NOT in the dump is therefore never applied by CI. Each entry
# below names such a migration. CI applies it, in the order listed, AFTER the
# >ledgerMax replay (so no reviewed migration sees a different catalog than
# before; see real-schema-ci.sh step 3b), with ON_ERROR_STOP. The migration file
# stays the single source of truth for the DDL; nothing is copied.
#
# RULES (enforced by real-schema-ci.sh; any violation fails the run):
#   - one bare file name per line, exactly as it appears in supabase/migrations/;
#     '#' starts a comment, blank lines are ignored;
#   - the 14-digit version must be <= baseline.json ledgerMax (above it the file
#     is already replayed, and listing it would apply it twice);
#   - the file must exist, and may appear only once;
#   - the file must apply cleanly onto the replayed schema (re-runnable DDL).
#
# REMOVAL. This is a stop-gap, not the canonical fix. The canonical fix is an
# owner-run regeneration of the baseline from production
# (node scripts/ci/generate-schema-baseline.js, then npm run db:drift). When a
# regenerated baseline.sql contains an entry's objects, delete the entry.
#
