## 6. Limitations

- `information_schema.role_table_grants` (q06) returned `[]`. That view only shows grants visible to the querying role (`supabase_read_only_user`), so grants were taken from `pg_class.relacl` instead (q01, q11). That is authoritative.
- The ledger rows' commit time is not recoverable (`track_commit_timestamp=off`). The writer of the 20261127000000 / 20270202000000 rows is unknown. Statement text was not read, by design.
- The q18 refusal: the client guard rejects the identifier `rollback`. The `rollback` column of the ledger was not read.
- When the authenticated grant on the prospect tables was revoked, and when `20261231000000` was applied, can only be bounded as "after 2026-11-10 06:41 UTC".
- The gate was run in a scratch copy without a git repo. Rule 6 does not use git; whether other git-dependent sub-checks changed was not tested.
- The trigger count in a CI/replay database was not measured here.
- Triggers on `api_idempotency_keys` were not queried.
